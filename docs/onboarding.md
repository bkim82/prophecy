# onboarding

Post-sign-up flow at `/welcome`: profile basics + a short survey, then the Pulse tutorial, then a personalized first move.

- Entry: Clerk mode keeps `ClerkProvider signUpForceRedirectUrl="/welcome"` (`app/auth/AuthProvider.tsx`). CDP mode: after a fresh sign-in from the modal (not a restored session) the bridge calls `needsOnboarding()` (`app/welcome/actions.ts`) and pushes `/welcome` when no `onboarding` row exists. No hard gate: a user who leaves midway isn't forced back; own `/profile` shows a "Finish setting up your account" card until they finish ([profiles.md](profiles.md)).
- Route: `app/welcome/page.tsx` (server). No viewer → `redirect("/")`; finished (`isOnboarded()`, `lib/onboarding.ts:9`) → `redirect("/")`. Prefills only stored name/handle/bio and the app-owned photo (`/api/profile/avatar`); no provider name/handle suggestion.
- Flow: `app/welcome/OnboardingFlow.tsx` (client), `STEPS` (`:46`), state resets on reload except what step 1 already saved:
  1. Profile — photo (optional, Clerk mode only via `useAppAuth().setProfileImage` after the text save; hidden under CDP, where Edit profile owns the photo), name + handle (required), bio (optional). Continue = `saveProfileBasics` (`app/profile/actions.ts:126`, same rules as Edit profile; location/website/banner untouched) — `saveProfileStep()` `:172`. Live handle hint: debounced `checkHandle` (`:141`) → "@x is yours" / "That handle is taken." (reserved mock-author handles + other users); hint only, the save re-checks.
  2. Why you're here — multi-select, ≥1: `GOALS` (`app/lib/onboardingQuestions.ts:7`): learn / community / strategies / profit.
  3. Experience — single, required: `EXPERIENCE` (`:15`): new / experienced / expert (1–3 bar meter). Plus optional multi "How do you like to trade?": `PACES` (`:22`): quick / day / hold.
  4. Interests — optional multi over `TOPICS` (`app/lib/topics.ts`); "Skip for now" when none.
  5. Finish — optional single "How did you hear about Prophecy?" (`REFERRALS`, `:29`; click again to clear) + required "I'm 18 or older" checkbox. "Enter Prophecy" = `finish()` (`:206`) → `finishOnboarding`.
- Tutorial stage: after the survey saves, `touring` (`:93`) renders `TutorialView onExit` in place of the welcome card (`:229`) — the full `/duel/tutorial` lessons + live round, skippable whole — "Skip tutorial & practice round" on its intro, a "Skip tutorial" / "Skip practice round" header pill on each step — or "Continue" on its done screen, all → finish screen without marking the tutorial done ([tutorial.md](tutorial.md)). Skipped when this browser already finished the tutorial (`hasFinishedTutorial()`, `:223`). `OnboardingFlow` owns the `<main>` (`.welcome-shell` for cards; the tutorial brings its own `.tut-shell`), not `app/welcome/page.tsx`. Reloading mid-tutorial lands on `/` (already onboarded).
- Finish screen: "You're in, <first word of the chosen name>." + `firstMovesFor(answers, hasFinishedTutorial())` (`app/lib/onboardingQuestions.ts:83`): lead = tutorial (`/duel/tutorial`) for `new` or `learn`; else `strategies` → 24h Portfolio (`/duel/portfolio`) when paces are picked and exclude `quick`, otherwise tutorial; else `profit` → Arena (`/duel`); else Omens (`/`). Tutorial finished → it drops out of the list and a tutorial lead becomes the Arena. Two more destinations as secondary cards, then "View your profile". No practice-round card (`/duel/btc/pulse?practice=1`) — the tutorial replaced it.
- Save: `finishOnboarding` server action (`app/welcome/actions.ts:31`) re-checks auth, ≥1 known goal, known experience, `adult === true`; drops unknown pace/topic/referral ids; timezone = browser IANA zone (`Intl`), pattern-checked. Upsert via `saveOnboarding()` (`lib/onboarding.ts:15`). No `refresh()` — the page would redirect away from the finish screen.
- Feed: the stored picks are the account's followed topics until it saves its own `topic_prefs` row (`accountTopics()` fallback, `lib/topicPrefs.ts:24`), so For You opens with one "Because you're interested in X" cover per pick ([feeds.md](feeds.md)). No picks → `[]`, not `DEFAULT_INTERESTS`: no covers or topic chips, just the "Pick interests" prompt, until they follow a topic or their activity infers one. Nothing is written to the browser. The DB copy is for data, not read back by the feed.
- Storage: `onboarding` table (`db/schema.ts:191`), one row per finished user: `goals`/`paces`/`interests` jsonb id arrays, `experience`, `referral` (nullable), `timezone` (nullable), `completed_at`. Ids, not copy — reword labels freely, but renaming/removing an id orphans old rows. Row present ⇒ user confirmed 18+. Created with a targeted `CREATE TABLE IF NOT EXISTS` matching the drizzle definition, not `db:push`.
- CSS: `.welcome-*` at the end of `app/globals.css` — glass card, segmented `.welcome-progress`, `.welcome-option`/`.welcome-chip` wrap visually hidden native inputs (`:has(input:checked)` / `:has(input:focus-visible)`), `.welcome-meter`, `.welcome-consent`, `.welcome-done`/`.welcome-move*`. Fields/avatar reuse `.profile-edit-*`; topic/referral chips reuse `.interest-option`. ≤560px: single-column cards.
- Not built: see [roadmap.md](roadmap.md) "Onboarding answers".
