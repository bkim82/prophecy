# messages

Direct messages between real accounts, X/Reddit-style: an envelope in the header opens a dock in the bottom-right corner. Friends (you follow each other) land in the Inbox; everyone else lands in Requests. Messages carry text, up to 4 photos and/or a shared post. Blocking someone from their profile stops it all.

- Header: `app/MessagesButton.tsx`, signed-in only, before the bell in both header layouts (`app/layout.tsx:73`, `:83`). Reuses `.notif-bell`/`.notif-badge`. Badge = unread messages, inbox + requests (`summary.inbox + summary.requests`), `9+` cap. Click toggles the dock (`aria-expanded`/`aria-controls="messages-dock"`).
- State: `app/lib/messages.ts` (client store, `useSyncExternalStore`): `open`, `view` (`DockView`: `list` + folder / `thread` + peer / `new`), `summary`. `showMessages(view)` opens it anywhere (profile Message button, Send post). `setMessageSummary` skips unchanged counts; `resetMessages` runs when the dock unmounts (sign-out). Also `postMessage()` (the one client sender, POST /api/messages/thread) and `usePeople(query)` (debounced `GET /api/messages/people`).
- Live updates: no extra poll. `POST /api/presence` (the 2s/15s header heartbeat, `app/LiveChallenges.tsx`) also returns `messages: MessageSummary | null` (`app/api/presence/route.ts:37`, `.catch(() => null)` so a messaging failure never breaks challenges); `heartbeat()` in `app/lib/liveChallenges.ts` feeds it to the store. `summary.latest` = newest message to or from you (ms); each dock view refetches when it moves.
- Dock: `app/MessagesDock.tsx`, mounted once (`app/layout.tsx:95`), `role="dialog"`, stays mounted `hidden` while closed, stays open across navigation, Esc closes. Links out of it (peer, shared post) close it ≤768px (`closeOnPhone`). Panes:
  - `ListPane` `:121` — "Messages" + New message + close; Inbox / Requests pills (`aria-pressed`, unread counts from `summary`); `GET /api/messages` rows (avatar, name, @handle, `playedLabel` time, preview = `messagePreview()`: text, else "Shared a post" / "Sent a photo" / "Sent N photos", "You: " on your own, bold + count when unread). Empty Inbox: "You have no messages"; empty Requests: "No message requests".
  - `ThreadPane` `:248` — back, peer avatar/name → their profile, close. Each message renders its shared post (`SharedPostCard` `:212`: author, text clamped to 5 lines, first photo; links to `/post/<id>`; null → "This post is no longer available."), then photos (`MessagePhotos` `:230`: 1 full width at its aspect ratio, 2–4 in a grid, each opens full size in a new tab), then the text bubble (yours right in `--brand`). A time under the last item of each run (`RUN_GAP_MS` `:34` = 5 min); scrolls to the bottom on new messages. `markConversationRead(handle, newestUnreadId)` when there's unread and the tab is visible, then sets the returned summary. Footer: blocked → `.messages-blocked` note ("You blocked @x. Unblock them on their profile…" / "You can't message @x."); request → "<name> wants to message you…" + Accept / Delete; else the composer: photo button (`ImageIcon`, hidden file input, JPEG/PNG/WebP/GIF ≤20 MB picked, ≤4) + paste, thumbnails with × (`.messages-attachments`, blob: URLs revoked on remove/send/unmount), textarea (Enter sends, Shift+Enter newline, `field-sizing: content`, ≤`MESSAGE_MAX_LENGTH`), Send enabled by text or photos. Photos go through `encodePhoto` (`app/lib/pickedPhoto.ts`, the composer's: ≤1600px JPEG stepped down to ≤1 MB; GIFs that fit as-is).
  - `NewMessagePane` `:544` — `usePeople` search; empty query lists friends under "Friends". Picking someone opens their thread (empty until you send).
- Send post: `SendPostButton` (`app/SharePostDialog.tsx:19`), the `.action-send` paper plane after Bookmark on every post with a page (`app/PostCard.tsx:494`; signed out → sign-in) → native `<dialog>` on the Edit profile shell (`.profile-edit.share-dialog`; stops click propagation so the card doesn't open the post): post preview, `usePeople` search, multi-select (≤10, chips with ×, ✓ rows), optional note, "Send" / "Send to N". One POST per person with `postId` (+ note); all sent → closes and opens the dock on that conversation (one) or the Inbox (several); partial failure keeps just the unsent people with the error.
- Profile: real accounts get ⋯ (Block, see below) + a round envelope `.profile-message-button` (`app/profile/[handle]/ProfileView.tsx:288`, `messageable` = `Boolean(target.userId)`; signed out → sign-in). Mock traders have neither.
- Folder rule: `folderFor(friends, accepted)` (`app/lib/messageRules.ts`): inbox if you follow each other (`friendIdsAmong`, `lib/follows.ts:49`) or your side is accepted; else request. Sending sets your side accepted, so conversations you start or reply to are in your inbox; a thread with nothing in it is yours to start. Unfollowing moves an unaccepted friend's thread back to Requests.
- Send: `POST /api/messages/thread` (`app/api/messages/thread/route.ts:50`) `{ handle, body?, photos?, postId? }` → 201 `{ message }`. Same-origin JSON check with a ~5.4 MB cap (`postsMutationFailure`), signed in, text normalized ≤1000, photos via `parsePhotos` (`lib/postInput.ts`, same byte checks as posts), `postId` must resolve (`sharedPostsFor`: mock feed/exclusive posts or a saved post not deleted), at least one of the three; recipient = real account by handle (not you; mock/unknown → 404 "That trader can't receive messages."), you need your own handle (403), no block either way (403 "You can't message @x."), ≤30/min and ≤1000/day (429, `messageCountSince`). Not a server action: photos outgrow its 1 MB body limit.
- Other writes (`app/messages/actions.ts`, server actions): `markConversationRead` (reads up to one of *their* message ids, never backwards), `acceptConversation`, `deleteConversation` (your side only: hides everything so far; a newer message from them is a fresh request). Read/delete return the fresh summary.
- Reads (`lib/messages.ts`, `force-dynamic`, `private, no-store`, 401 signed out): `GET /api/messages` → `{ inbox, requests }` (`conversationsFor` `:143`: DISTINCT ON peer via a subquery, newest 50); `GET /api/messages/thread?handle=` → `ThreadView` (`threadWith` `:174`, newest 100 oldest-first, `blocked`: `"by-you" | "by-them" | null` with no messages when set; 404 for you/mock/unknown; doesn't mark read); `GET /api/messages/people?q=` → `{ people }` (friends or `searchProfiles`, minus you and blocks, 8); `GET /api/messages/media/[id]/[n]` → photo bytes for the sender/recipient only (`messageImage` `:232`, else 404; `private, max-age=3600`). Peers without a handle are skipped everywhere. Shared posts and photo URLs resolve per read (`messageViews`), never stored as copies.
- Blocks (`lib/blocks.ts`, real accounts by user id, either direction counts for both): `saveBlock` inserts the row, deletes follows both ways, cancels pending challenges between them, and deletes each one's reposts of the other's saved posts (others' reposts stay); unblocking only deletes the row. Effects: send refused; conversation hidden from both docks and both badges (`blockedIdsFor` in `conversationsFor`/`messageSummaryFor`); `threadWith` returns no messages + `blocked`; `people` search skips them; `followProfile` refuses; their saved posts — and followed accounts' reposts of them — leave your Omens feed, and yours leave theirs (`blockedHandlesFor` in `app/page.tsx`); replying to or reposting each other's saved posts is refused (403, `app/api/posts/[id]/replies` + `reshare`; undoing a repost still works); each other's replies are hidden (`repliesFor`) and left out of reply/repost counts (`withEngagement`, `blockedAccountsFor`), everyone else still sees them; their posts come back with `post.blocked`, which disables Repost (`app/RepostMenu.tsx`) and swaps the reply box for "You can't reply to this post." (`ReplyComposer` `blocked`, `.reply-blocked`). Profile UI: [profiles.md](profiles.md) Block.
- Storage (`db/schema.ts:557`): `direct_messages` (id, sender, recipient, `body` ≤1000 default '', `post_id`, `created_at`; indexes on recipient/sender + time; no self-messages), `direct_message_media` (`:574`, message id + position 0–3, mime, base64, width/height), `direct_threads` (`:591`, PK user+peer: `last_read_at`, `accepted_at`, `cleared_at`) — `db/messages.sql` (carries ALTERs for the text-only first version); `blocks` (`:606`, PK blocker+blocked, index on blocked) — `db/blocks.sql`. Applied to the dev Neon DB. Times on the DB clock.
- CSS (`app/globals.css:194`): `.messages-dock` 380px, bottom-right flush to the bottom edge, `z-index: 55`; ≤768px full screen (`:2287`). `.messages-head/-tabs/-row/-avatar(--sm/--xs)/-thread/-bubble*/-photos/-post*/-composer(-row)/-attachments/-send/-request*/-blocked/-search/-empty`; `.share-*` (`:1640`); `.action-send` (`:698`); `.profile-more`/`.profile-unblock` (`:1541`).

## Gaps

- Polling only (heartbeat every 2s visible / 15s hidden); no push, typing indicators or read receipts.
- No report or mute; no limit on messages to someone who hasn't accepted (only the per-sender rate limit).
- Blocks don't hide likes, their own profile page (posts and Comments tab stay viewable, just not replyable/repostable), or your posts on theirs; replies to mock posts are hidden from you but still allowed; mock traders can't be blocked.
- Threads show the newest 100 messages (no older-history paging); lists show the newest 50 conversations.
- Photos are base64 in Postgres like post photos (should move to object storage before launch); no GIF picker, link previews, editing or unsending; the full-size photo opens in a new tab rather than a viewer.
- Can't delete an inbox conversation from the UI (only requests); `deleteConversation` itself works for any.
- No notification in the bell for new messages; the envelope badge is the only signal.
