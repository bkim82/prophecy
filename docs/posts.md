# posts

Saved omens: posts from both composers persist in Neon Postgres and every viewer sees them. A post stores a *reference* to its trade, never the numbers; the trade is resolved from the DB, with an ownership check, each time the post is rendered.

- Schema (`db/schema.ts:377`): `posts` (author id + write-time `author_name`/`author_handle` snapshot, `content` ≤280, `topics` jsonb ≤3 incl. custom `#name`, `trade_ref`, `trade_roi_at_post`, `gif`, `poll_choices` + `poll_ends_at`, `created_at`, soft-delete `deleted_at`), `post_media` (`:402`, ≤4 photos per post, base64 like profile banners, pk post+position), `poll_votes` (`:415`, pk post+user). DB-level CHECKs mirror the app limits.
- Migration: `db/posts.sql`, additive + idempotent, applied with the unpooled URL in one transaction (not `db:push`, same rule as `db/embedded-wallet.sql`). Applied to the shared dev Neon DB 2026-10-21 (every checkout's `.env.local` points at it).
- Write: `POST /api/posts` (`app/api/posts/route.ts:23`): same-origin JSON check (`mutationRequestFailure` `lib/requestSecurity.ts:17`, `maxBodyBytes` raised to ~5.5 MB for photos) → `getViewer()` (401) → `parsePostInput` (`lib/postInput.ts:36`) → rate limit 5/min + 200/day per author (`postCountSince` `lib/posts.ts:59`, counted from `posts`, so it works in both auth modes) → trade must resolve as the viewer's own (`tradeReceiptsFor`, else 403); an open one's current ROI is stored as `trade_roi_at_post` → author = `profiles.displayName` / provider name (never "You", else "Prophecy trader"), handle only from `profiles.handle` (unique; a provider username could collide) → `createPost` (`lib/posts.ts:26`, post + photos in one `db.batch` transaction) → 201 `{ id }`. Any DB failure → 503 "Posting is unavailable right now".
- Input rules (`lib/postInput.ts`): content trimmed ≤280; topics via `isTopicId` (built-in or well-formed custom), deduped; `tradeId` must match `TRADE_REF` (`app/lib/trades.ts`); `gif` ∈ `GIFS`; poll 2–4 trimmed choices ≤25 + duration in `POLL_DURATIONS_MS` (`:14`, 1h–7d); photos ≤4, base64, type/size checked from the bytes (`inspectPostImage`, `app/lib/postImage.ts`: JPEG/PNG/WebP/GIF ≤1 MB, ≤4096px; GIF header parsing added to `imageInfo` `app/lib/profileImage.ts:106`); photos / GIF / poll mutually exclusive; needs text, a trade, photos or a GIF.
- Trade resolution (`tradeReceiptsFor` `lib/trades.ts:118`): batches refs → `positions` by id (must be the author's) and settled `matches` by id (author must be player 1 or 2, receipt from their side). Open positions: settles each owner's past-due session first (`settlePortfolioIfDue`, idempotent), then prices live (`getTokenPrices`, cached). Shared mapping with the picker's `recentTradesFor` (`:86`) via `portfolioReceipts` (`:14`) / `arenaReceipts` (`:56`). Unresolvable ref → `Post.tradeUnavailable` → `TradeUnavailable` (`app/TradeCard.tsx:130`, dashed, no numbers).
- Read: `feedPosts` (`lib/posts.ts:201`, newest 30) for `app/page.tsx` (failure → mock feed only, logged), `savedPost` (`:207`) for `/post/[id]` (mock ids first, then the DB; uuid-shaped ids only). `toFeedPosts` (`:124`): live name/handle from `profiles` (else snapshot; no handle → none shown), photo URLs `/api/posts/<id>/media/<n>` (bytes never inlined), poll `counts` + viewer's `yourVote` + `closed`, `mine` = author is the viewer, `timestamp` via `playedLabel` (server-side, SSR-safe). Open trades on a card: live ROI + "When posted" (`roiAtPost`) in the prices row.
- Other routes: `DELETE /api/posts/[id]` (owner only, soft delete, 404 otherwise; FeedSwitcher hides optimistically and restores on failure, `app/FeedSwitcher.tsx:139`), `POST /api/posts/[id]/vote` `{ choice | null }` (`votePoll` `lib/posts.ts:80`: upsert / clear; 404 no poll, 409 closed, 400 bad choice), `GET /api/posts/[id]/media/[n]` (public, `max-age=3600` so deletes take effect; 404 once deleted).
- Clients: both composers call `publishPost` (`app/lib/postApi.ts`) — signed out, Post opens sign-in and keeps the draft. `/compose` encodes photos in the browser (`encodePhoto` `app/compose/Composer.tsx:69`: GIF ≤1 MB as-is, else JPEG ≤1600px stepping quality 0.86→0.6 to fit 1 MB), then `markFreshPost` (`app/lib/freshPost.ts`) + `router.push("/")`/`refresh()`; the feed flashes that id. `PostPoll` votes through the API on saved posts (optimistic, rolled back on failure; signed out → sign-in). `app/compose/page.tsx` passes the author's recent custom topics (`recentCustomTopicsBy` `lib/posts.ts:190`) for reuse.
- Tests: `lib/postInput.test.ts` (input rules), `app/api/posts/route.test.ts` (sign-in, origin, validation, someone else's trade → 403, rate limit, server-derived author, `trade_roi_at_post` only for open trades, delete owner-only, vote outcomes). DB paths were verified once against the dev DB with throwaway rows (removed).
- Not saved yet: likes, reposts/vouch/defy, replies, bookmarks (still local, see `feeds.md`); real authors' names don't link to a profile (no public profiles for real users). Custom topic names are public with no moderation. Open trades update on page load only (no live polling).
