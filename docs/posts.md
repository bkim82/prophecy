# posts

Saved omens: posts from the composer persist in Neon Postgres and every viewer sees them. A post stores a *reference* to its trade, never the numbers; the trade is resolved from the DB, with an ownership check, each time the post is rendered.

- Schema (`db/schema.ts:377`): `posts` (author id + write-time `author_name`/`author_handle` snapshot, `content` ≤280, `topics` jsonb ≤3 incl. custom `#name`, `trade_ref`, `trade_roi_at_post`, `gif`, `poll_choices` + `poll_ends_at`, `created_at`, soft-delete `deleted_at`), `post_media` (`:402`, ≤4 photos per post, base64 like profile banners, pk post+position), `poll_votes` (`:415`, pk post+user). DB-level CHECKs mirror the app limits.
- Migration: `db/posts.sql`, additive + idempotent, applied with the unpooled URL in one transaction (not `db:push`, same rule as `db/embedded-wallet.sql`). Applied to the shared dev Neon DB 2026-10-21 (every checkout's `.env.local` points at it).
- Write: `POST /api/posts` (`app/api/posts/route.ts:23`): same-origin JSON check (`mutationRequestFailure` `lib/requestSecurity.ts:17`, `maxBodyBytes` raised to ~5.5 MB for photos) → `getViewer()` (401) → `parsePostInput` (`lib/postInput.ts:36`) → rate limit 5/min + 200/day per author (`postCountSince` `lib/posts.ts:59`, counted from `posts`, so it works in both auth modes) → trade must resolve as the viewer's own (`tradeReceiptsFor`, else 403); an open one's current ROI is stored as `trade_roi_at_post` → author = `profiles.displayName` / provider name (never "You", else "Prophecy trader"), handle only from `profiles.handle` (unique; a provider username could collide; `authorFor` `app/api/posts/author.ts`, shared with replies) → `createPost` (`lib/posts.ts:26`, post + photos in one `db.batch` transaction) → 201 `{ id }`. Any DB failure → 503 "Posting is unavailable right now".
- Input rules (`lib/postInput.ts`): content trimmed ≤280; topics via `isTopicId` (built-in or well-formed custom), deduped; `tradeId` must match `TRADE_REF` (`app/lib/trades.ts`); `gif` ∈ `GIFS`; poll 2–4 trimmed choices ≤25 + duration in `POLL_DURATIONS_MS` (`:14`, 1h–7d); photos ≤4, base64, type/size checked from the bytes (`parsePhotos`, shared with DM photos; `inspectPostImage`, `app/lib/postImage.ts`: JPEG/PNG/WebP/GIF ≤1 MB, ≤4096px; GIF header parsing added to `imageInfo` `app/lib/profileImage.ts:106`); photos / GIF / poll mutually exclusive; needs text, a trade, photos or a GIF.
- Trade resolution (`tradeReceiptsFor` `lib/trades.ts:118`): batches refs → `positions` by id (must be the author's) and settled `matches` by id (author must be player 1 or 2, receipt from their side). Open positions: settles each owner's past-due session first (`settlePortfolioIfDue`, idempotent), then prices live (`getTokenPrices`, cached). Shared mapping with the picker's `recentTradesFor` (`:86`) via `portfolioReceipts` (`:14`) / `arenaReceipts` (`:56`). Unresolvable ref → `Post.tradeUnavailable` → `TradeUnavailable` (`app/TradeCard.tsx:130`, dashed, no numbers).
- Read: `feedPosts` (`lib/posts.ts:201`, newest 30) for `app/page.tsx` (failure → mock feed only, logged), `savedPost` (`:210`) for `/post/[id]` (mock ids first, then the DB; uuid-shaped ids only). `toFeedPosts` (`:124`): live name/handle from `profiles` (else snapshot; no handle → none shown), photo URLs `/api/posts/<id>/media/<n>` (bytes never inlined), poll `counts` + viewer's `yourVote` + `closed`, `mine` = author is the viewer, `timestamp` via `playedLabel` (server-side, SSR-safe). Open trades on a card: live ROI + "When posted" (`roiAtPost`) in the prices row.
- Other routes: `DELETE /api/posts/[id]` (owner only, soft delete, 404 otherwise; FeedSwitcher hides optimistically and restores on failure, `app/FeedSwitcher.tsx:139`), `POST /api/posts/[id]/vote` `{ choice | null }` (`votePoll` `lib/posts.ts:80`: upsert / clear; 404 no poll, 409 closed, 400 bad choice), `GET /api/posts/[id]/media/[n]` (public, `max-age=3600` so deletes take effect; 404 once deleted).
- Engagement (`lib/engagement.ts`; migration `db/engagement.sql`, same apply rule, applied to the shared dev Neon DB 2026-10-21): `post_likes` (`db/schema.ts:434`, pk post+user), `post_reshares` (`:445`, one per user per post: kind repost/vouch/defy + words ≤280; a change replaces it and resets `created_at`), `post_replies` (`:460`, uuid, author id + name/handle snapshot like `posts`, content 1–280, `edited_at`, soft-delete `deleted_at`), `reply_likes` (`:478`, pk reply+user), `clash_votes` (`:488`, pk post+user, side 0/1, mock clash posts only). `post_id` is a saved post id *or* a mock post id, so the mock feed's engagement saves too; mock counts are the base saved ones add to. Targets (`engagementTarget` `:31`): engageable mock posts (not streak/promo/clash) or live saved posts, else 404. Routes (same-origin + sign-in, like the others): `POST /api/posts/[id]/like` `{ liked }`, `POST /api/posts/[id]/reshare` `{ kind | null, text? }` (403 vouch/defy on your own saved post), `GET /api/posts/[id]/replies` (public; `repliesFor` `:308` → `toReplies` `:261` = live (not deleted) saved replies newest first ≤100 with live author from `profiles`, `mine`/`edited`/`saved`, then `POST_REPLIES`, each with saved likes + the viewer's `liked`), `POST /api/posts/[id]/replies` `{ content }` → 201 `{ reply }` (author via `authorFor`, 10/min + 300/day per author via `replyCountSince`, DB failure → 503), `POST /api/posts/[id]/replies/[replyId]/like` `{ liked }` (`replyExists` `:319`: a live reply under that post), `PATCH /api/posts/[id]/replies/[replyId]` `{ content }` → `{ content }` (`editReply` `:238`, author only, sets `edited_at`) and `DELETE` (`deleteReply` `:247`, author only, soft delete) — 404 for anyone else's, `POST /api/posts/[id]/clash` `{ side: 0 | 1 | null }` (`voteClash` `:63`, 404 unless a mock clash). Reads: `withEngagement` (`:83`, one batch per list; failure → posts unchanged, logged) adds counts (replies minus deleted) + the viewer's `liked`/`yourReshare`, and a clash's side votes + `yourVote`, on `/` (saved + mock in one call), `/post/[id]`, `/exclusive` and profiles' Omens tabs. Followers: `followedReshares` (`:173`) = reposts from the last 7 days by real accounts the viewer follows (joined through `follows`), newest first ≤50, as `Share`s with their words; `/` passes them to `FeedSwitcher` and loads any reposted saved post older than the newest 30 (`savedPostsByIds` `lib/posts.ts:210`) into the main list. Profiles: `accountActivity` (`:340`) = a real account's saved posts (`postsBy` `lib/posts.ts:228`) + newest 30 live replies with their parent post, for `/profile/[handle]` and your own `/profile`. Client: `app/lib/engagementApi.ts` (see `feeds.md`). Across a block either way with a saved post's author (`lib/blocks.ts`) replies and reposts are refused (403), each other's replies are hidden and uncounted, and their posts get `blocked` (see [messages.md](messages.md) Blocks).
- Clients: the composer calls `publishPost` (`app/lib/postApi.ts`) — signed out, Post opens sign-in and keeps the draft. `/compose` encodes photos in the browser (`encodePhoto` `app/compose/Composer.tsx:69`: GIF ≤1 MB as-is, else JPEG ≤1600px stepping quality 0.86→0.6 to fit 1 MB), then `markFreshPost` (`app/lib/freshPost.ts`) + `router.push("/")`/`refresh()`; the feed flashes that id. `PostPoll` votes through the API on saved posts (optimistic, rolled back on failure; signed out → sign-in). `app/compose/page.tsx` passes the author's recent custom topics (`recentCustomTopicsBy` `lib/posts.ts:190`) for reuse.
- Tests: `lib/postInput.test.ts` (input rules), `app/api/posts/route.test.ts` (sign-in, origin, validation, someone else's trade → 403, rate limit, server-derived author, `trade_roi_at_post` only for open trades, delete owner-only, vote outcomes), `app/api/posts/engagement.test.ts` (like/repost/reply sign-in + origin, 404 targets, words trimmed/≤280, no vouch/defy on your own post, server-derived reply author, reply rate limit, 503, reply likes scoped to their post, reply edit/delete owner-only, clash side validation). DB paths (posts, engagement, then follows/reposts/clash votes/reply edit+delete/profile activity) were verified against the dev DB with throwaway rows and a throwaway profile (removed).
- Not saved yet: bookmarks (still local, see `feeds.md`). Replies notify no one (no notifications for replies, likes or reposts); a repost with words isn't its own post. Custom topic names are public with no moderation. Open trades update on page load only (no live polling).
