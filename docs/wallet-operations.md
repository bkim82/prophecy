# Embedded wallet operations

- Launch state is fail-closed: leave `EMBEDDED_WALLET_AUTH_ENABLED`, `WALLET_TRANSACTIONS_ENABLED`, `NEXT_PUBLIC_WALLET_TRANSACTIONS_ENABLED`, `CDP_PAYMASTER_DECODER_VERIFIED`, `WALLET_ONRAMP_ENABLED`, and `NEXT_PUBLIC_WALLET_EXPORT_ENABLED` unset until their gates pass.
- Required server secrets: `SESSION_SECRET` (32+ chars), `DATABASE_URL`, migration-only `DATABASE_URL_UNPOOLED`, `CDP_API_KEY_ID`, `CDP_API_KEY_SECRET`, and eventual upstream Paymaster/Onramp credentials. Never prefix server credentials with `NEXT_PUBLIC_`.
- Required origin pins: exact HTTPS `APP_ORIGIN`; separate CDP projects for local/Base Sepolia and production/Base; no localhost production origin; CDP first-party-cookie limited access is a production blocker.
- Schema gate: apply additive `db/embedded-wallet.sql` (not `db:push`, which would drop `main`-only tables until branches merge) with a direct Neon connection in a non-production branch first; verify `users`, `profiles`, `app_sessions`, `request_rate_limits`, `transaction_intents`, `wallet_spend_counters`, `wallet_audit_events`, and `onramp_orders` before enabling embedded auth.
- Reset gate: run `npm run db:reset:prelaunch` as a dry run first; apply only in `local|development|test|preview` with `--apply --confirm=RESET_PRELAUNCH_ACCOUNT_DATA`; production is hard-blocked (`scripts/prelaunch-account-reset.mjs`).
- Signing kill switch: unset/set `WALLET_TRANSACTIONS_ENABLED=false`; read-only balances, holdings, prices, and activity remain available. Browser UI additionally requires `NEXT_PUBLIC_WALLET_TRANSACTIONS_ENABLED=true`.
- Sponsorship kill switch: unset `CDP_PAYMASTER_DECODER_VERIFIED`; `/api/wallet/intents/[id]/submit` and `/api/wallet/paymaster` fail closed before upstream sponsorship.
- Onramp/export kill switches: unset `WALLET_ONRAMP_ENABLED` and `NEXT_PUBLIC_WALLET_EXPORT_ENABLED`; copy-address deposits remain available.
- Monitor `wallet_audit_events` counts by event/failure code, `wallet_spend_counters` by UTC day/token, submitted intents without hashes for 2+ minutes, submitted intents without terminal receipts, provider 429/5xx rates, sponsorship spend, and Onramp order terminal ratios. Alerts must not include cookies, authorization headers, calldata, provider payloads, or private material.
- Incident: disable transaction/Paymaster/Onramp/export gates; keep reads online; revoke compromised API/Paymaster/Onramp credentials; revoke all application sessions if browser auth may be affected; preserve audit/intents; reconcile known user-operation hashes; notify affected users with hashes/status only.
- Session rotation: rotate `SESSION_SECRET` to invalidate every application session, then require a fresh CDP token exchange. Treat this as a global sign-out and announce it operationally.
- Provider credential rotation: create replacement credential, deploy it server-side, verify validation/reconciliation in the non-production project, revoke the old credential, and inspect error/usage telemetry. Never overlap local and production project credentials.
- Rollback: turn off feature gates before reverting code/schema; do not drop wallet/session tables during an incident; retain durable intent/audit rows for reconciliation. Clerk fallback may be used only before final cutover and only while its runtime dependency/config remains.
- Launch evidence: archived Base Sepolia sign-in/link/MFA/session tests, decoded send and exact-input swap vectors, Paymaster nested-batch bypass tests, simulation and receipt/revert/drop tests, CSP report review, dependency advisory disposition, origin/project screenshots, quota/alert tests, and credential/session rotation drill.
