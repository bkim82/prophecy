# profiles

Mock user profiles at `/profile/[handle]`. UI-only: no backend, no persistence. The signed-in viewer's own profile is `/profile` (below) — same view, partly real.

- Route: `app/profile/[handle]/page.tsx` (server). URL is the handle without `@` (`/profile/ren.eth`); looks up `@${handle}` via `getProfile()`, `notFound()` for unknown handles (`:13`). Renders `ProfileView` + `ProfileAchievements` (not the feed's `FeedSidebar`) in `.feed-shell`.
- Data: `app/lib/mockProfiles.ts` — `PROFILES` (`:20`, name/rank/bio/joined/followers/following; rank matches the author's feed posts), `profileHref()` (`:39`, undefined when no profile → callers render plain text), `profileActivity()` (`:49`) derives tabs from feed mocks: omens = their `GLOBAL_POSTS`+`EXCLUSIVE_POSTS` (rank overridden with the profile's), comments = their `POST_REPLIES` entries paired with the parent post, trades = omens that carry a `call`.
- Portfolios: `app/lib/mockPortfolios.ts` `PORTFOLIOS` — static 24h-session snapshots shaped like [portfolio.md](portfolio.md) (Base meme coins, spot or 1/2/3/5× lots). Kept out of `mockProfiles.ts` because `PostCard` (client) imports `profileHref` from there.
- Rank gate: `canViewPortfolio()` (`app/lib/rank.ts:70`) — viewer ≥ profile rank. `rankScore()` (`:58`): tier × 10 + division, tiers bronze < silver < gold < platinum < diamond < prophet < oracle, divisions count up (Gold I < Gold II < Gold III), bare tier ("Oracle") sorts below its divisions. Viewer is hardcoded `VIEWER_RANK = "Gold II"` (`:67`).
- Gate runs on the server (`page.tsx:16`): a locked portfolio is passed as `null`, so its data never reaches the client; `LockedPortfolio` (`ProfileView.tsx:553`) shows blurred empty placeholder rows, required rank vs viewer rank badges, and a `/duel` CTA.
- `app/profile/[handle]/ProfileView.tsx` (client): hero = avatar (tier ring/glow via `data-rank`) → large `RankBadge` overlapping the avatar's bottom edge (`.profile-rank` gives it an opaque backing) → name/handle → bio → Joined · Followers · Following → Follow toggle (local only; initial state from `FOLLOWED_HANDLES`, follower count ±1). Tabs in order Omens / Comments / Trades / Portfolio (`:36`, `useState`, resets on reload; Portfolio shows `LockIcon` when locked). Trades tab reuses `MarketCallCard` (one-row layout at this width) with a fulfilled/broken/liquidated/open summary from `callTrack()` state.
- Right rail: `app/profile/[handle]/ProfileAchievements.tsx` (server component; `children` render under it — the highlight reel). `.feed-sidebar.profile-rail` drops the feed rail's sticky/`max-height`/own-scroll, so the page scrolls as one and the rail can make it taller than a short tab. Achievements panel = two hero cards (Highest Elo + peak `RankBadge`, card tinted by peak tier via `data-rank`; Biggest ROI = `signedPct` + market glyph + direction/leverage + month) over `sidebar-row` stats (longest win streak, win rate of N calls, best 24h session, Arena duels won). "No records yet." when the handle has no entry. (The trophy case that sat below it was replaced by the highlight reel.) The panel itself is `AchievementsPanel` (same file), which the rail wraps. Hero is compact: 80px avatar (72px ≤768px), 128px banner (100px), 8px gaps.
- Phones (≤768px): the rail is hidden and Achievements / Highlight reel become faces of the hero card — `app/profile/[handle]/ProfileShowcase.tsx` wraps the hero (`ProfileView` passes its `showcase` prop: `AchievementsPanel` + `HighlightReel`, built by both pages; the reel face is omitted when a mock trader has no pins). Top-left toggle = pill with the current face's icon + name + one dot per face (accent = rank color, gold on the reel; pulses 3× on load via `profile-face-beckon`), opening a Profile / Achievements / Highlight reel menu (`.theme-menu-popover` styling). Bannerless heroes get a 52px header strip so the pill clears the avatar. Panel faces visually hide their own `h3` (the pill names the face) and center their content; the reel stacks compact cards (2-line clamp, Unpin in the top row) to fit the card — no sideways scroll. Picking a face flips the card: `data-flip="out"` spins it edge-on (`profile-flip-out`), `onAnimationEnd` swaps `data-showing`, `data-flip="in"` spins back with overshoot + a glint sweep, then the face's cards rise in staggered (`--d`). Reduced motion swaps instantly. All faces share one grid cell (inactive = `visibility: hidden`), so the card keeps the tallest face's height. State is local, resets on reload; desktop shows only the profile face.
- Records data: `app/lib/mockAchievements.ts` — `RECORDS` (`:27`) hand-picked career numbers per handle (no Elo system exists; feed mocks only hold 0–2 trades per author, so nothing is derived from `profileActivity()`); `peakRank` must stay ≥ the profile's rank, and each trader's first `PINNED_OMENS` entry must equal their `bestTrade` (both hand-maintained). Also `ACCURACY` (`:42`), `STYLES` (`:58`), `PINNED_OMENS` (`:75`) — see below.
- How they trade (`app/lib/profileTraits.ts`, client-safe; all on both profile kinds):
  - Archetype chip under the name (`ProfileView.tsx:155`, `data-archetype` tints it): `archetypeFor()` (`:53`) runs `ARCHETYPE_RULES` (`:46`) in order, first match wins — The Daredevil (avg leverage ≥ 20×) → The Contrarian (fade/short share ≥ 55%) → The Patient (avg hold ≥ 48h) → The Swift (Pulse-round share ≥ 60%); none → no chip. Inputs = `STYLES[handle]` (mock traders) / `VIEWER_STYLE` (`app/lib/mockViewer.ts`, mock: settled Pulse rounds keep no leverage/side). Icons `SwiftIcon`/`PatientIcon`/`ContrarianIcon`/`DaredevilIcon` in `app/icons.tsx`.
  - `TradeDossier` (`ProfileView.tsx:262`) under the stats: Signature = `signatureAsset()` (`:19`, most calls, tie → more accurate) with its glyph (`ASSET_META`, adds SOL `◎`/`--market-sol`); Accuracy = `accuracyLine()` top 3 by accuracy, `≥60%` green / `<45%` red. Mock traders: `ACCURACY[handle]`. Own profile: real, `marketAccuracyFor()` (`lib/match.ts:261`) — per market, rounds finished with P&L > 0 ÷ rounds with P&L ≠ 0 (`title` says so).
  - Highlight reel (`app/profile/[handle]/HighlightReel.tsx`): a rail panel under Achievements (passed as `ProfileAchievements` children by both pages): ≤ `MAX_PINS` (3) cards with the gold `✦ Fulfilled` chip and `--gold` edge/wash of a fulfilled call, stacked in one column; ≤960px the panel spans the row with cards side by side (`auto-fit`); ≤768px it lives in the hero instead (below). Hidden when a mock trader has no pins. Mock traders: `PINNED_OMENS[handle]` (omen text, asset, side, leverage, ROI, month). Own profile (`editable`): pinned won matches (opponent, round, P&L, net Embers), `n/3` in the header, one dashed open-slots hint, Unpin per card (its own `togglePinnedMatch` transition; hover-revealed, always visible on `hover: none`).
- Own profile: `app/profile/page.tsx` (server), opened from the header avatar menu's Profile item (`app/AccountMenu.tsx:38`, `UserButton.Link` ahead of Clerk's Manage account). Signed out → `redirectToSignIn()` (`:60`). Renders the same `ProfileView` + `ProfileAchievements` with `self` set:
  - Real: join month (Clerk); photo = Clerk `imageUrl` only when `user.hasImage` (else the gradient initial; plain `<img>`); everything the editor saves — name (falls back to Clerk's), handle, bio (`white-space: pre-line`), location, website, banner — read via `storedProfileFor()` (`lib/profile.ts:20`, never selects the banner bytes). No handle → hero shows a "Choose your @handle" button (`ProfileView.tsx:149`) that opens the editor. Rank = `VIEWER_RANK`; Following = `FOLLOWED_HANDLES.length`.
  - Hero: optional `.profile-banner` (`Profile.banner`, preset or `/api/profile/banner?v=<updatedAt>`), location/website line (`.profile-meta`, `:163`; link is `target=_blank rel="noopener noreferrer nofollow ugc"`), Edit profile in place of Follow (`:191`). `CopyEarningsCard` (`:295`) under the hero: traders who copied you / trades copied / $ earned.
  - Editor: `app/profile/EditProfileDialog.tsx` (`:72`) — native `<dialog>` mounted only while open (fresh draft each time), full-screen ≤620px. Banner: upload (center-cropped to 3:1, ≤1500px wide, JPEG re-encoded down to ≤ `BANNER_MAX_BYTES` client-side, `cropBanner` `:52`), one of 6 Prophecy-motif `BANNER_PRESETS` (`app/lib/profileEdit.ts:51`: The Oracle's Eye sunburst, Destiny track ✦, Doom hazard stripes, Tarot card back, Embers, Eclipse — swatches draw each at 4× and scale down so px-sized motifs survive), or remove. Photo: pick/remove; sent to Clerk `user.setProfileImage()` (`:159`) only after the text save succeeds, then `router.refresh()`. Fields with counters/limits from `app/lib/profileEdit.ts` (`PROFILE_LIMITS`: name 50, handle 20, bio 160, location 30, website 100); live handle check disables Save. Footer "Email, password & security" closes the dialog then opens Clerk's `openUserProfile()` (it can't stack over a native modal).
  - Save: `saveProfile` server action (`app/profile/actions.ts:38`) re-validates everything — lengths, handle pattern (3–20 `a–z0–9_.`, no edge/double dots, stored lowercase without `@`), `RESERVED_HANDLES` (`:23`: every mock author + admin/me/you/oracle/prophecy/support), website → http(s) only via `normalizeWebsite`, banner type (JPEG/PNG/WebP) and size — then one upsert (`saveStoredProfile`, `lib/profile.ts:82`; unique-index violation → "That handle is taken.") and `refresh()`. Preset and uploaded image are mutually exclusive; `keep` leaves the banner alone.
  - Pins: Pin/Pinned button (`PinButton`, `ProfileView.tsx:446`) on Matches rows that `isPinnableMatch()` (`profileTraits.ts:67`: won and P&L > 0 — a "won" round can still be red); disabled at 3 unless already pinned; icon-only ≤620px. `togglePinnedMatch` server action (`app/profile/actions.ts:108`) re-checks ownership/eligibility via `settledMatchesByIds()` (`lib/match.ts:275`), caps at 3, keeps pin order, `savePinnedMatches()` (`lib/profile.ts:39`, doesn't bump `updatedAt` since that versions the banner URL), `refresh()`. The page re-fetches pins by id (they can be older than the listed 20) and drops any that stopped qualifying.
  - Storage: `profiles` table (`db/schema.ts:148`, one row per Clerk user, unique `handle`, `pinned_matches` jsonb `:159`). Created with a targeted `CREATE TABLE IF NOT EXISTS` (+ `ALTER TABLE … ADD COLUMN IF NOT EXISTS pinned_matches`) matching the drizzle definition, not `db:push`. Uploaded banners are base64 in `banner_image`, served by `GET /api/profile/banner` (owner-only — real profiles aren't public — `private, immutable` cache, URL versioned by `updatedAt`).
  - Tabs: `SELF_TABS` (`ProfileView.tsx:44`) puts Matches first and default. `MatchesTab` (`:383`): lifetime `W · L · T · ±N Embers` summary from `matchRecordFor()` (`lib/match.ts:238`, one aggregate over every settled match), then the newest 20 from `settledMatchesFor()` (`:231`) mapped by `historyEntryFor()` (`:295`): W/L/T tile, `vs <opponent>` (Clerk `@username`, else first name, else "Opponent"; never last name/email), market · round length · stake · relative time (formatted server-side, `app/lib/playedLabel.ts`; opponent lookup `lib/opponentNames.ts`, shared with the lobby's `GET /api/match/recent`), net Embers (±wager, matches `settleFundsIfNeeded`) and both players' round P&L. Only `settled` rows — a round nobody polled past its deadline stays `countdown` and doesn't list. Empty → Arena link.
  - Omens/Comments/Trades are empty (posting isn't persisted); Portfolio links to `/duel/portfolio` instead of rendering the session (`:248`).
  - Mock (`app/lib/mockViewer.ts`, same for every account): followers, copy earnings, `VIEWER_STYLE` (archetype), and `VIEWER_RECORDS` for the rail — except `duelsWon`, which the page replaces with the real `record.won`.
